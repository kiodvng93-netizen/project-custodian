# Project Custodian — Audit (2026-11-14, v4.6)

Scope: every live file under `js/`, `index.html`, `PROJECT_STATE.md`, the previous audit (`docs/AUDIT-2026-11-12.md`) and git history. This is a code-reading audit with numeric checks of the balance formulas. I did not play-test it in a browser.

**Short version:** the engineering cleanup since the last audit is real: ES modules, Pixi with Y-sorting, save defaults, weapon run-configs, a spatial grid. But **the v4.6 headline features are not actually in the game**, and the roadmap says they are. The deeper problem is design, not code. The run has no goal or ending, enemies outrun the player within 3 minutes, and five different "bank your scrap" systems compete for the same decision.

---

## 1. Roadmap claims vs. code ("ghost features")

`PROJECT_STATE.md` marks these `[x]`. They are scaffolding only: config values, HUD and render code exist, but the gameplay hook was never written. Commit `ff05486 4.6` touched neither `player.js` nor `enemies/enemy.js`, where the hooks would live.

| Claimed (v4.6) | Reality |
|---|---|
| Ring 2+ frontal armor (±65°, bullets do 20%) | `Enemy.takeDamage(amount, sx, sy, suppressLoot)` has **4 params** (`js/enemies/enemy.js:58`). Every caller's 5th `armorPiercing` arg is ignored. No code ever sets `hasFrontalArmor` or `armorFlashTimer`. The armor overlay (`js/world/hazards.js:136`) never draws anything. |
| Slime/web zones slow the player 50% and block Cruise | `RingHazardManager.sampleAt()` (`js/world/hazards.js:37`) is **never called**. `player.inSlimeZone` and `currentTerrainMult` are never set. The zones are decoration. |
| Workshop perk **ALL-TERRAIN TRACKS** | It costs real banked scrap and **does nothing** (`js/main.js:109`). Players pay for nothing. |
| Draft card **ALL-TERRAIN CLEATS** | Only the +8% speed works. Its `slimeSlowResist` is also never reset on death (`js/player.js:198`), so after two picks the card is filtered out for the rest of the session (`js/weapons/upgrades.js:212`). |
| Ring 2/3/4 content | Nests, ruins, chests and outposts all spawn inside `ring1Radius × 0.92` (`js/world/manager.js:53,83`). Beyond 15,000 px there is nothing except inert circles, plus a HUD banner reading "OUTER MIRE (ARMORED FOES)" that is false. |

**Root cause (process):** the "one isolated chat per folder" workflow (`PROJECT_STATE.md §4 Data Contracts`). A feature that spans `world/`, `weapons/`, `enemies/` and `player.js` got its `world/` and `weapons/` halves; the `enemies/` and `player.js` halves never landed. Nothing checks that "done" means "works in the game".

## 3. Balance: the numbers

**Enemies outrun the player by minute 3.** Speed escalates +4.5% per 40 s wave, capped at 1.55×. A sprout (158 base) passes the player's 180 base speed at **wave 5 (2:40)** and reaches 245 px/s at wave 15. Cruise (261) is the only escape, and taking a hit cancels it. In a game built around *traveling* an open world, losing the ability to disengage this early undercuts the core fantasy. Damage climbs too: a sprout hits for 36 at wave 15 against a 100-HP robot.

| Wave (time) | Enemy HP | Enemy dmg | Enemy speed |
|---|---|---|---|
| 5 (2:40) | ×1.56 | ×1.36 | ×1.18 |
| 10 (6:00) | ×2.26 | ×1.81 | ×1.41 |
| 15 (9:20) | ×2.96 | ×2.26 | ×1.55 |
| 20 (12:40) | ×3.66 | ×2.71 | ×1.55 |

**XP curve is geometric (×1.25 per level).** Level 11 needs 280 XP total, level 21 needs 3,392 and level 31 needs 32,893. Most enemies give 1 XP. Player power growth stalls in the very minutes when enemy scaling is steepest.

> **Correction (later the same day, from bot simulations):** this was wrong. Kill volume is far higher than assumed. After ~3 minutes a bot that never dies earns ~50 XP/s (~30 kills/s) and reaches level ~30 by minutes 7–9. A flat additive curve would push players past level 100 in 10 minutes. The geometric curve stays. The real XP problem is bursts: 8–10 level-ups within 1–2 seconds when a large XP pile is collected at once.

**Meta progression is weak.** MOTOR TUNING gives +8 speed (4%) per rank, against an enemy +55%. Scrap per full-clear run is roughly 130 (≈26 chests × 4, plus nests and the landmark), and enemies drop no scrap. Fine for a prototype, but the Workshop doesn't change how a run feels.

**Flamer (cone) aims where you walk**, not at enemies (`meleeArchetypes.js:196`). In a horde game you mostly walk *away* from enemies, so the flamer points at empty ground.

## 4. Code health and performance

**Good since last audit:** ES modules, `state.js` as the hub, weapon `runConfigs` cloned per run, save defaults merged, spatial grid used by most weapons, swept-AABB walls, Pixi pooling with Y-sorting and shadows, archive folder, slimmer `PROJECT_STATE.md`.

**Still to fix:**
- **The wallet lives in Telemetry.** `Telemetry.metrics.resourcesCollected.techScrap` is the player's carried scrap, read and written from 8 files. Move it to `state.run.cargo`.
- **`pixi.js@8` loaded unpinned from a CDN** (`index.html:11`). Any v8.x release can break the game, and it can't run offline. Pin an exact version, or vendor it.
- **No `CLAUDE.md`** (last audit's #2 action). Every AI session still starts by re-reading files.
- **Dead files:** `js/world.js2`, `js/weapons/arsenal.js2`, `js/weapons/evolutions.js2`; `PickupManager.update`; `SpriteManager.isReady`; all `render(ctx)` Canvas fallbacks duplicate Pixi. Delete the `.js2` files (git keeps them).
- **Per-frame garbage:** `SpatialGrid` builds string keys on every insert and query, and `getNearby` allocates a new array on every call (~400+ per frame from `moveWithSeparation`). `GroundZone` spreads a new array per zone per frame. Use integer keys and a reused output array.
- **Projectiles skip the grid:** each one loops over every enemy and nest every frame (`js/weapons/projectiles.js:38`).
- **Assets:** 14 PNGs, ~33 MB, 1536×1024 with white backgrounds. All are chroma-keyed on the CPU at boot with no loading screen. Same as last audit.
- **UI hit-testing is duplicated** between `render/ui.js` and `main.js` click handlers (magic numbers in two places).

## 5. Design: is it interesting, unique, does it have a chance?

**What the game is right now:** a survivors-like (auto-weapons, level-up drafts, evolutions) set in a large open disc. You carry scrap from chests and nests and bank it before you die. A hub heals you but punishes camping. One boss drops a core that repairs a landmark. Waves escalate forever.

**What's genuinely good:**
- **The greed loop** (carry loot → risk → bank) fused with horde combat is the strongest idea here. It's the tension that makes extraction games work, and survivors-likes mostly lack it.
- **Hub anti-camping (Hive Wrath)** is a memorable rule with a clear warning, and good fiction.
- **The fiction:** a lone custodian robot purifying a corrupted biosphere, with a tech-vs-bio evolution theme. It's coherent and pitchable.
- **The surge / ebb / breather rhythm** gives combat a pulse instead of a flat ramp.

**Where it stands in the market:** survivors-likes have been one of Steam's most crowded genres since 2022. The closest relatives:
- **Deep Rock Galactic: Survivor** already does survivors-like plus mining and extraction.
- **Dome Keeper** already does "go out, come back before the wave, upgrade".
- **Brotato** owns "robot + waves + shop".

Custodian's mix isn't unprecedented, so it has to win on **execution and one sharp hook**, not on a feature list.

**Honest chances as it stands: low.** There is no run goal or ending, no audio, no title, game-over or tutorial screens, placeholder art, and two marquee features that don't work. Nothing yet would make a 10-second clip stand out. **With focus: a real niche chance**, because the greed-extraction hook is good and the code base is now in decent shape to iterate on.

### What I would do differently

1. **Give a run an ending.** Bring "evac shuttle" forward from the backlog: kill the Warden → carry the core to the Purifier → call evac → survive 60 s → the run is won and all cargo is banked. Today the only way a run ends is death, so every run ends in failure.
2. **Make carried scrap the difficulty knob, instead of hidden time.** "The Hive smells your cargo": spawn pressure and elite chance scale with unbanked scrap. That ties combat to the extraction decision and is a more distinctive hook than "+14% HP per wave". Keep the wave rhythm, but **show** escalation on screen.
3. **Collapse the five banking systems into two.** Hub deposit, outposts, purifier transfer, fast-travel tax and death insurance all answer one question. Keep **outposts** (risky, local, bonus) and **evac** (end of run), and cut or merge the rest.
4. **Shrink and densify Ring 1** (radius ~6–8k instead of 15k). At 180–260 px/s, reaching a nest takes 30–60 s of walking, and Brotato's appeal is density.
5. **Cap enemy speed below the player's** (e.g. sprout max ≈ 0.95 × base player speed). Let elites and dashers be the fast threats. Flatten the XP curve to additive steps.
6. **Make evolutions carry upgrades over** (and add cards for evolved weapons). Make the flamer auto-aim.
7. **Freeze new rings until Ring 1 is fun.** Either finish the armor and slime hooks or delete them. Don't stack Ring 3/4 on top.
8. **Add audio now, not at v5.0.** A dozen Web Audio SFX is the cheapest game-feel upgrade available, and you already have hit-stop and trauma to sync with.
9. **Process:** add a `CLAUDE.md`; only tick `[x]` after playing the feature; keep one cross-folder feature per session instead of one folder per chat. A tiny headless sim (spawn player and enemies, run 600 frames in Node, assert armor reduces damage) would have caught §1.
